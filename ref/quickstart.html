머리말

본서는 라라벨로 한 개 이상의 실 서비스를 출시한 PHP 개발자를 대상으로, 심포니 8.0 환경에서 작은 쇼핑몰을 1주일 내에 출시할 수 있는 최소 지식을 제공한다.

심포니 공식 문서가 “핵심 컴포넌트”로 분류하는 11개 주제를 한 프로젝트(작은 쇼핑몰) 안에서 일관된 코드로 보여준다.

  5. Session — Flash, 세션 기반 장바구니

1.1 시작 — symfony new와 도커

본 절은 빈 심포니 8.0 webapp 프로젝트를 만들고 PostgreSQL을 도커로 띄우는 절차를 정리한다.

Symfony CLI 설치

$ curl -sS https://get.symfony.com/cli/installer | bash
$ export PATH="$HOME/.symfony5/bin:$PATH"
$ symfony check:requirements

프로젝트 생성

$ symfony new shop --version="8.0.*" --webapp
$ cd shop
$ symfony serve -d

--webapp 플래그는 Doctrine·Twig·Form·Validator·Security·Mailer·Messenger·Maker 번들을 일괄 설치한다. 라라벨의 composer create-project laravel/laravel 직후 상태에 해당한다.

도커로 데이터베이스

# compose.yaml (--webapp 플래그가 자동 생성)

    image: postgres:16-alpine
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: app
      POSTGRES_PASSWORD: !ChangeMe!
    ports: ["5432:5432"]
    volumes: ["db_data:/var/lib/postgresql/data"]
volumes: { db_data: }
$ docker compose up -d
$ symfony console doctrine:database:create --if-not-exists

Symfony CLI는 도커 컴포즈를 감지해 DATABASE_URL을 자동으로 환경변수에 노출한다. 별도 .env 수정 없이 바로 사용 가능하다.

1.3 첫 컨트롤러 — invokable

심포니 8.0의 권장 컨트롤러 패턴은 단일 액션 invokable 클래스다. __invoke() 메서드를 통해 컨트롤러 클래스 자체가 하나의 호출 가능 객체로 동작한다.

// src/Controller/HomeController.php
namespace App\Controller;

use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

final class HomeController extends AbstractController
{
    #[Route('/', name: 'home', methods: ['GET'])]
    public function __invoke(): Response
    {
        return $this->render('home.html.twig', [
            'title' => '심포니 쇼핑몰',
        ]);
    }
}

라라벨 대응

// 라라벨
Route::get('/', HomeController::class)->name('home');

class HomeController extends Controller
{
    public function __invoke() {
        return view('home', ['title' => '쇼핑몰']);
    }
}

AbstractController가 제공하는 헬퍼

  • render($template, $context) — Twig 응답
  • json($data, $status) — JSON 응답
  • redirectToRoute($name, $params) — 302 리다이렉트
  • createNotFoundException() · createAccessDeniedException()
  • addFlash($type, $msg) · getUser()
  • denyAccessUnlessGranted($attr, $subject)
  • isCsrfTokenValid($id, $token)

이 7개 헬퍼면 컨트롤러의 90%를 작성할 수 있다.

1.4 요청 처리 흐름

HTTP 요청이 HttpKernel에 도착해서 응답으로 반환되기까지의 흐름은 다음과 같다.

sequenceDiagram participant B as Browser participant K as HttpKernel participant R as Router participant C as Controller participant T as Twig B->>K: HTTP 요청 K->>R: match(request) R-->>K: 컨트롤러 콜러블 K->>C: __invoke(args) C->>T: render(template, ctx) T-->>C: HTML C-->>K: Response K-->>B: 응답
그림 1. 요청-응답 처리 흐름

주요 이벤트

각 단계에서 EventDispatcher가 이벤트를 발행한다. 사용자 코드는 #[AsEventListener]로 임의 단계에 후킹할 수 있다.

  • kernel.request: Firewall, Locale 결정
  • kernel.controller: 컨트롤러 결정 직후 (IsGranted, ParamConverter)
  • kernel.view: 컨트롤러가 Response가 아닌 값을 반환했을 때
  • kernel.response: 응답 직전 (보안 헤더, Profiler)
  • kernel.terminate: 응답 전송 후 (메트릭, 비동기 디스패치)
  • kernel.exception: 예외 발생 시

라라벨의 미들웨어 파이프라인이 단일 추상이라면, 심포니는 위 6개 이벤트 + 리스너 우선순위 + Firewall이라는 다층 구조로 같은 책임을 분담한다.

2부

Doctrine ORM

2.1 Product 엔티티

Doctrine은 Active Record(라라벨 Eloquent)가 아닌 Data Mapper 패턴을 따른다. 엔티티는 데이터의 모양만 담고, 영속화는 EntityManager가, 질의는 Repository가 책임진다.

// src/Entity/Product.php
namespace App\Entity;

use App\Repository\ProductRepository;
use Doctrine\ORM\Mapping as ORM;
use Symfony\Component\Validator\Constraints as Assert;

#[ORM\Entity(repositoryClass: ProductRepository::class)]
#[ORM\Index(columns: ['created_at'], name: 'ix_product_created_at')]
class Product
{
    #[ORM\Id, ORM\GeneratedValue, ORM\Column]
    private ?int $id = null;

    #[ORM\Column(length: 200)]
    #[Assert\NotBlank, Assert\Length(max: 200)]
    private string $name = '';

    #[ORM\Column(length: 220, unique: true)]
    private string $slug = '';

    #[ORM\Column]
    #[Assert\PositiveOrZero]
    private int $priceKrw = 0;

    #[ORM\Column]
    private int $stock = 0;

    #[ORM\Column(type: 'datetime_immutable')]
    private \DateTimeImmutable $createdAt;

    public function __construct() {
        $this->createdAt = new \DateTimeImmutable();
    }
    // 게터·세터는 make:entity --regenerate로 생성
}

매핑 메타데이터는 PHP 속성(#[ORM\*])으로 표현한다. #[Assert\*] 제약이 같은 위치에 있어 데이터 정의의 단일 출처(SSOT) 원칙이 유지된다.

2.2 Order · OrderItem 관계

주문은 헤더(Order) + 라인(OrderItem) 두 엔티티로 구성한다.

erDiagram USER ||--o{ ORDERS : places ORDERS ||--|{ ORDER_ITEM : contains PRODUCT ||--o{ ORDER_ITEM : referenced USER { int id PK string email UK } PRODUCT { int id PK string name int price_krw int stock } ORDERS { int id PK int user_id FK string status int total_krw datetime placed_at } ORDER_ITEM { int id PK int order_id FK int product_id FK int quantity int unit_price_krw }
그림 2. 쇼핑몰 도메인 ER

ORDER_ITEM.unit_price_krw가 분리되어 있는 점에 주목한다. 상품 가격은 변경되어도, 과거 주문의 라인 가격은 시점값을 유지해야 회계 무결성이 보장된다.

#[ORM\Entity, ORM\Table(name: 'orders')]
class Order {
    #[ORM\OneToMany(targetEntity: OrderItem::class,
        mappedBy: 'order', cascade: ['persist'], orphanRemoval: true)]
    private Collection $items;

    #[ORM\ManyToOne(inversedBy: 'orders')]
    #[ORM\JoinColumn(nullable: false)]
    private User $customer;
}

orders로 테이블명을 명시한 이유는 order가 PostgreSQL 예약어이기 때문이다.

2.3 마이그레이션

DoctrineMigrationsBundle은 “엔티티 ↔ 스키마” 차분을 자동으로 추출한다. 사용자가 SQL을 직접 작성하는 일은 거의 없다.

차분 생성과 적용

$ php bin/console make:migration
> Generated migrations/Version20260503120000.php

$ php bin/console doctrine:migrations:migrate
> WARNING! Are you sure? (yes/no) [yes]:
$ php bin/console doctrine:migrations:status

생성된 파일 구조

final class Version20260503120000 extends AbstractMigration
{
    public function getDescription(): string {
        return 'Initial schema: product, orders, order_item, app_user';
    }

    public function up(Schema $schema): void {
        $this->addSql('CREATE TABLE product (...)');
        $this->addSql('CREATE TABLE orders (...)');
        $this->addSql('CREATE INDEX ix_product_created_at ...');
    }

    public function down(Schema $schema): void { /* 역순 DROP */ }
}

운영 권장

  • 마이그레이션 파일은 커밋 필수. 동료·CI·운영의 스키마 일관성.
  • 운영 배포: doctrine:migrations:migrate --no-interaction --allow-no-migration.
  • 자동 생성 SQL을 반드시 검토한다. 컬럼 이름 변경은 “DROP+CREATE”로 해석되어 데이터 손실로 이어질 수 있다. 이 경우 up/down을 수동으로 ALTER COLUMN ... RENAME TO로 교체.
  • 롤백: doctrine:migrations:migrate prev (단계별), first (모두 롤백).

라라벨의 php artisan migrate · migrate:rollback과 동일 위상이며, “엔티티 차분 자동 추출”이 가장 큰 차이다.

2.4 Fixtures (시드 데이터)

개발·테스트 환경에서 일관된 초기 상태를 보장하기 위한 시드 도구. 라라벨 Seeder에 대응한다.

$ composer require --dev doctrine/doctrine-fixtures-bundle
// src/DataFixtures/AppFixtures.php
namespace App\DataFixtures;

use App\Entity\Product;
use Doctrine\Bundle\FixturesBundle\Fixture;
use Doctrine\Persistence\ObjectManager;

final class AppFixtures extends Fixture
{
    public function load(ObjectManager $em): void
    {
        foreach (range(1, 20) as $i) {
            $p = (new Product())
                ->setName(sprintf('상품 %02d', $i))
                ->setSlug(sprintf('item-%02d', $i))
                ->setPriceKrw(rand(5, 50) * 1000)
                ->setStock(rand(0, 50));
            $em->persist($p);
        }
        $em->flush();
    }
}

실행 옵션

$ php bin/console doctrine:fixtures:load
  # 모든 테이블 truncate 후 적재 (확인 프롬프트)

$ php bin/console doctrine:fixtures:load --append
  # 기존 데이터 유지

$ php bin/console doctrine:fixtures:load --group=demo
  # 특정 그룹만

의존성 있는 픽스처

여러 픽스처 클래스로 분할하고 실행 순서가 필요하면 DependentFixtureInterface::getDependencies() 또는 OrderedFixtureInterface::getOrder()를 구현한다. setReference()·getReference()로 픽스처 간 객체 공유가 가능하다.

운영 환경에서는 픽스처를 사용하지 않는다 (운영 데이터는 마이그레이션 또는 별도 데이터 스크립트로 관리).

2.5 QueryBuilder

커스텀 쿼리는 Repository 클래스의 메서드로 응집한다. ServiceEntityRepository를 상속하면 컨테이너에 자동 등록되어 컨트롤러·서비스에서 타입 힌트만으로 주입된다.

// src/Repository/ProductRepository.php
namespace App\Repository;

use App\Entity\Product;
use Doctrine\Bundle\DoctrineBundle\Repository\ServiceEntityRepository;
use Doctrine\Persistence\ManagerRegistry;

/** @extends ServiceEntityRepository<Product> */
class ProductRepository extends ServiceEntityRepository
{
    public function __construct(ManagerRegistry $registry) {
        parent::__construct($registry, Product::class);
    }

    public function findBySlug(string $slug): ?Product {
        return $this->findOneBy(['slug' => $slug]);
    }

    public function searchByKeyword(string $q, int $limit = 50): array {
        return $this->createQueryBuilder('p')
            ->andWhere('p.name LIKE :q')
            ->andWhere('p.stock > 0')
            ->setParameter('q', '%'.$q.'%')
            ->orderBy('p.createdAt', 'DESC')
            ->setMaxResults($limit)
            ->getQuery()->getResult();
    }

    public function paginate(int $page, int $perPage = 12): array {
        return $this->createQueryBuilder('p')
            ->orderBy('p.createdAt', 'DESC')
            ->setFirstResult(($page - 1) * $perPage)
            ->setMaxResults($perPage)
            ->getQuery()->getResult();
    }
}

안전과 성능

  • 모든 변수는 :placeholder + setParameter()로 바인딩 — SQL 인젝션 차단.
  • N+1 회피: ->leftJoin('p.images', 'i')->addSelect('i')로 FETCH JOIN.
  • 대량 조회: ->getQuery()->getArrayResult()로 엔티티 hydrate 생략.

Form & Validation

3.1 FormType 작성

Form 컴포넌트는 폼의 정의·렌더링·검증·객체 매핑을 한 클래스(FormType)로 응집한다. 라라벨의 FormRequest와 “Blade 폼”의 책임을 합친 위치에 있다.

// src/Form/ProductType.php
namespace App\Form;

use App\Entity\Product;
use Symfony\Component\Form\AbstractType;
use Symfony\Component\Form\Extension\Core\Type\{IntegerType, TextType, TextareaType};
use Symfony\Component\Form\FormBuilderInterface;
use Symfony\Component\OptionsResolver\OptionsResolver;

class ProductType extends AbstractType
{
    public function buildForm(FormBuilderInterface $b, array $opts): void
    {
        $b->add('name', TextType::class, ['label' => '상품명'])
          ->add('description', TextareaType::class, [
              'label' => '설명', 'required' => false,
          ])
          ->add('priceKrw', IntegerType::class, [
              'label' => '가격 (원)',
              'attr' => ['min' => 0, 'step' => 100],
          ])
          ->add('stock', IntegerType::class, [
              'label' => '재고',
              'attr' => ['min' => 0],
          ]);
    }

    public function configureOptions(OptionsResolver $r): void
    {
        $r->setDefaults([
            'data_class' => Product::class,
        ]);
    }
}

data_class가 지정되면 폼 데이터가 자동으로 해당 엔티티 인스턴스에 매핑된다. “신규 등록”과 “수정”이 동일 FormType을 공유한다 (빈 인스턴스 vs 기존 인스턴스만 다름).

주요 빌트인 타입: TextType · EmailType · PasswordType · IntegerType · NumberType · ChoiceType · FileType · CollectionType · EntityType(Doctrine 연동) · RepeatedType · HiddenType · SubmitType.

3.2 컨트롤러와 handleRequest

표준 7행 패턴: 폼 생성 → 요청 바인딩 → 검증 후 영속화 → 리다이렉트 / 재렌더.

// src/Controller/ProductCreateController.php
namespace App\Controller;

use App\Entity\Product;
use App\Form\ProductType;
use Doctrine\ORM\EntityManagerInterface;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\{Request, Response};
use Symfony\Component\Routing\Attribute\Route;

#[Route('/admin/products/new', name: 'product_create')]
final class ProductCreateController extends AbstractController
{
    public function __invoke(
        Request $request, EntityManagerInterface $em,
    ): Response {
        $product = new Product();
        $form = $this->createForm(ProductType::class, $product);
        $form->handleRequest($request);

        if ($form->isSubmitted() && $form->isValid()) {
            $em->persist($product);
            $em->flush();
            $this->addFlash('success', '상품이 등록되었습니다.');
            return $this->redirectToRoute('product_show', [
                'slug' => $product->getSlug(),
            ]);
        }
        return $this->render('product/new.html.twig', ['form' => $form]);
    }
}

Twig 렌더링

3.3 Validation 제약

검증 제약(#[Assert\*])은 엔티티 위치에 둔다. 같은 엔티티를 여러 폼에서 재사용해도 동일 제약이 자동 적용된다.

use Symfony\Component\Validator\Constraints as Assert;

class Product
{
    #[ORM\Column(length: 200)]
    #[Assert\NotBlank(message: '상품명을 입력하세요.')]
    #[Assert\Length(min: 2, max: 200)]
    private string $name = '';

    #[ORM\Column]
    #[Assert\PositiveOrZero(message: '가격은 0 이상이어야 합니다.')]
    #[Assert\Range(min: 0, max: 99_999_999)]
    private int $priceKrw = 0;

    #[ORM\Column(length: 220, unique: true)]
    #[Assert\Regex('/^[a-z0-9-]+$/', message: '슬러그는 영소문자·숫자·하이픈만.')]
    private string $slug = '';
}

자주 쓰는 제약

  • NotBlank · NotNull · IsNull
  • Email · Url · Ip · Hostname
  • Length(min, max) · Range(min, max)
  • Choice(choices) · Country · Currency · Locale
  • Regex(pattern) · Type('integer') · Json
  • Positive · PositiveOrZero · Negative
  • File(maxSize, mimeTypes) · Image(maxWidth, maxHeight)
  • UniqueEntity(fields) — 클래스 레벨 (DB 검색)
  • Callback — 임의 검증 로직
  • NotCompromisedPassword — Have I Been Pwned 검사

검증 그룹

groups: ['Default', 'create']로 컨텍스트별 제약을 분리한다. 폼 측에서 'validation_groups' => ['create']로 활성 그룹 지정.

4.4 Voter — 인스턴스 단위 인가

ROLE만으로는 표현할 수 없는 “이 사용자가 이 객체에 대해 X 행위가 가능한가” 같은 질문에 답하는 컴포넌트.

// src/Security/OrderVoter.php
namespace App\Security;

use App\Entity\{Order, User};
use Symfony\Component\Security\Core\Authentication\Token\TokenInterface;
use Symfony\Component\Security\Core\Authorization\Voter\Voter;

final class OrderVoter extends Voter
{
    public const VIEW = 'view';
    public const CANCEL = 'cancel';

    protected function supports(string $att, mixed $subject): bool
    {
        return in_array($att, [self::VIEW, self::CANCEL], true)
            && $subject instanceof Order;
    }

    protected function voteOnAttribute(
        string $att, mixed $subject, TokenInterface $token,
    ): bool {
        $user = $token->getUser();
        if (!$user instanceof User) return false;

        $isOwner = $subject->getCustomer()->getId() === $user->getId();
        $isAdmin = in_array('ROLE_ADMIN', $user->getRoles(), true);

        return match ($att) {
            self::VIEW   => $isOwner || $isAdmin,
            self::CANCEL => $isOwner
                && $subject->getStatus() === 'pending',
        };
    }
}

호출 방법

// 컨트롤러 — 명시적 거부
$this->denyAccessUnlessGranted('view', $order);

// 컨트롤러 — 분기
if ($this->isGranted('cancel', $order)) { /* ... */ }

// 라우트 속성
#[IsGranted('cancel', subject: 'order')]
public function cancel(Order $order): Response { /* ... */ }

Voter는 autoconfigure로 자동 등록된다. 다중 Voter 결과는 기본 “affirmative” 전략으로 결합 (한 Voter라도 grant면 허용).

5.1 Session 기본

심포니의 세션은 “읽기·쓰기 발생 시점”에 자동 시작된다 (lazy start). 응답이 자동으로 private 캐시로 표시되므로, 정적 캐시가 필요한 페이지에서는 세션 접근을 회피한다.

접근 방법

// 컨트롤러 — Request에서 직접
public function __invoke(Request $request): Response
{
    $session = $request->getSession();
    $session->set('locale', 'ko');
    $locale = $session->get('locale', 'en');  // 두 번째 인자는 기본값
}
// 서비스 — RequestStack 주입
namespace App\Service;

use Symfony\Component\HttpFoundation\RequestStack;

final readonly class ViewCounter
{
    public function __construct(private RequestStack $requests) {}

    public function increment(): int
    {
        $session = $this->requests->getSession();
        $count = $session->get('view.count', 0) + 1;
        $session->set('view.count', $count);
        return $count;
    }
}

세션 API

$session->set('key', $value);
$session->get('key', $default);
$session->has('key');
$session->remove('key');
$session->clear();           // 전체 비움
$session->invalidate();      // ID 회전 + 비움 (보안)
$session->migrate(true);     // ID 회전 (로그인 시 권장)

구성

// config/packages/framework.php
$framework->session()
    ->cookieLifetime(0)        // 브라우저 종료 시 만료
    ->cookieSecure('auto')     // HTTPS이면 자동 secure
    ->cookieHttpOnly(true)
    ->cookieSamesite('lax')
    ->handlerId(null);         // null = PHP 기본 (파일)

운영에서 다중 서버 구성이면 handlerId를 Redis('%env(REDIS_URL)%') 또는 PdoSessionHandler로 변경한다.

5.2 세션 기반 장바구니

비로그인 사용자도 사용 가능한 장바구니의 가장 단순한 구현. 항목 ID와 수량을 세션 배열에 저장한다.

// src/Cart/Cart.php
namespace App\Cart;

use App\Repository\ProductRepository;
use Symfony\Component\HttpFoundation\RequestStack;

final readonly class Cart
{
    public function __construct(
        private RequestStack $requests,
        private ProductRepository $products,
    ) {}

    public function add(int $productId, int $qty = 1): void {
        $items = $this->items();
        $items[$productId] = ($items[$productId] ?? 0) + $qty;
        $this->save($items);
    }

    public function remove(int $productId): void {
        $items = $this->items();
        unset($items[$productId]);
        $this->save($items);
    }

    public function setQuantity(int $productId, int $qty): void {
        $items = $this->items();
        if ($qty <= 0) unset($items[$productId]);
        else $items[$productId] = $qty;
        $this->save($items);
    }

    public function clear(): void { $this->save([]); }

    /** @return array<int, int> productId => qty */
    public function items(): array {
        return $this->requests->getSession()->get('cart', []);
    }

    public function totalKrw(): int {
        $sum = 0;
        foreach ($this->items() as $id => $qty) {
            $p = $this->products->find($id);
            if ($p) $sum += $p->getPriceKrw() * $qty;
        }
        return $sum;
    }

    private function save(array $items): void {
        $this->requests->getSession()->set('cart', $items);
    }
}

로그인 시 영속 카트로 전환하려면 InteractiveLoginEvent 리스너에서 세션 항목을 사용자 Cart 엔티티로 머지한다.

6.1 Console — #[AsCommand]

심포니 8.0의 권장 콘솔 명령 패턴은 #[AsCommand] 속성을 가진 invokable 클래스다. extends Command가 더 이상 필수가 아니며, 부트스트랩 코드가 한층 줄었다.

// src/Command/CreateProductCommand.php
namespace App\Command;

use App\Entity\Product;
use Doctrine\ORM\EntityManagerInterface;
use Symfony\Component\Console\Attribute\AsCommand;
use Symfony\Component\Console\Command\Command;
use Symfony\Component\Console\Style\SymfonyStyle;

#[AsCommand(
    name: 'app:product:create',
    description: '상품을 빠르게 등록한다.',
    aliases: ['app:p:create'],
)]
final class CreateProductCommand
{
    public function __construct(
        private EntityManagerInterface $em,
    ) {}

    public function __invoke(SymfonyStyle $io): int
    {
        $name = $io->ask('상품명');
        $price = (int) $io->ask('가격(원)', '10000');

        $product = (new Product())
            ->setName($name)
            ->setPriceKrw($price)
            ->setSlug(strtolower(preg_replace('/[^a-z0-9]+/i', '-', $name)));
        $this->em->persist($product);
        $this->em->flush();

        $io->success(sprintf('상품 #%d 등록됨.', $product->getId()));
        return Command::SUCCESS;
    }
}

실행

$ php bin/console app:product:create
$ php bin/console app:p:create        # alias
$ php bin/console list app             # app: 그룹 전체
$ php bin/console help app:product:create

반환값은 Command::SUCCESS(0), Command::FAILURE(1), Command::INVALID(2) 중 하나.

6.2 Console — 인자 · 옵션 · IO

심포니 8은 #[Argument]·#[Option] 속성으로 인자·옵션을 메서드 시그니처에 직접 선언한다.

use Symfony\Component\Console\Attribute\{Argument, Option};

#[AsCommand(name: 'app:user:promote', description: '사용자를 관리자로 승격')]
final class PromoteUserCommand
{
    public function __construct(
        private UserRepository $users,
        private EntityManagerInterface $em,
    ) {}

    public function __invoke(
        #[Argument('승격할 사용자 이메일')]
        string $email,

        #[Option(name: 'role', shortcut: 'r',
            description: '부여할 ROLE')]
        string $role = 'ROLE_ADMIN',

        #[Option(name: 'dry-run',
            description: '실제 저장 없이 미리보기')]
        bool $dryRun = false,

        SymfonyStyle $io,
    ): int {
        $user = $this->users->findOneBy(['email' => $email])
            ?? throw new \RuntimeException("$email 없음");

        $roles = array_unique([...$user->getRoles(), $role]);

        if ($dryRun) {
            $io->note(sprintf('[dry-run] %s → %s',
                $email, implode(', ', $roles)));
            return Command::SUCCESS;
        }

        $user->setRoles($roles);
        $this->em->flush();
        $io->success("$email 에 $role 부여 완료.");
        return Command::SUCCESS;
    }
}

SymfonyStyle 주요 메서드

  • $io->title(...) · section(...) · text(...)
  • $io->success(...) · warning(...) · error(...) · note(...)
  • $io->ask(...) · askHidden(...) · confirm(...) · choice(...)
  • $io->table($headers, $rows)
  • $io->progressStart(N) · progressAdvance() · progressFinish()

6.3 Cache — Symfony Contracts

심포니 Cache 컴포넌트는 두 인터페이스를 제공한다.

  • CacheInterface (Symfony Contracts): 콜백 기반 고수준 API. 권장.
  • CacheItemPoolInterface (PSR-6): 명시적 아이템 관리.

기본 사용

use Symfony\Contracts\Cache\CacheInterface;
use Symfony\Contracts\Cache\ItemInterface;

final readonly class FeaturedProducts
{
    public function __construct(
        private CacheInterface $cache,
        private ProductRepository $products,
    ) {}

    public function __invoke(): array
    {
        return $this->cache->get('featured.products',
            function (ItemInterface $item): array {
                $item->expiresAfter(600);   // 10분
                $item->tag(['product.featured']);
                return $this->products->findFeatured(8);
            });
    }
}

풀 정의

// config/packages/cache.php
return static function (FrameworkConfig $framework): void {
    $cache = $framework->cache();
    $cache->app('cache.adapter.redis');
    $cache->defaultRedisProvider('%env(REDIS_URL)%');

    $cache->pool('catalog.cache')
          ->adapters(['cache.adapter.redis_tag_aware'])
          ->defaultLifetime(3600)
          ->tags(true);
};

풀 이름은 camelCase 변수명으로 자동 와이어링된다. catalog.cache → $catalogCache.

태그 무효화

$this->catalogCache->invalidateTags(['product.featured']);
// 'product.featured' 태그가 붙은 모든 항목 일괄 삭제

주요 어댑터: filesystem, redis, redis_tag_aware, memcached, apcu, pdo, array.

6.4 HTTP Cache

리버스 프록시(CDN·Varnish·Cloudflare) 앞단에 둘 때 백엔드 부하를 극적으로 감소시킨다. 심포니 자체에도 HttpCache 미들웨어가 포함된다.

응답 헤더 설정

final class CatalogController extends AbstractController
{
    #[Route('/products', name: 'product_index')]
    public function __invoke(ProductRepository $repo): Response
    {

        $response->setSharedMaxAge(300);   // CDN/프록시 5분
        $response->headers->set('Vary', 'Accept-Language');
        return $response;

}

운영 권장

  • 컨테이너 환경: stdout/stderr 출력 → 외부 도구(Loki·Datadog·CloudWatch) 수집.
  • JSON 포맷터(monolog.formatter.json)로 구조화 — 검색·필터에 유리.
  • WebProcessor: IP·URL·user-agent 자동 첨부.
  • UidProcessor: 요청별 고유 ID 부여 (분산 트레이싱과 결합).

6.6 Error Pages

운영 환경(APP_ENV=prod)에서는 예외 발생 시 사용자에게 친화적인 HTML 페이지가 노출된다. 기본 템플릿을 사용자 템플릿으로 오버라이드할 수 있다.

커스텀 템플릿 위치

templates/
└── bundles/
    └── TwigBundle/
        └── Exception/
            ├── error404.html.twig    # 상태 코드별
            ├── error500.html.twig
            └── error.html.twig       # 폴백 (그 외 모든 에러)

TwigErrorRenderer는 (1) error{statusCode}.html.twig → (2) error.html.twig 순으로 검색한다.

404 템플릿 예

{# templates/bundles/TwigBundle/Exception/error404.html.twig #}
{% extends 'base.html.twig' %}

{% block title %}페이지를 찾을 수 없습니다{% endblock %}

{% block body %}
  <div class="error-page">
    <h1>404</h1>
    <p>요청하신 페이지를 찾을 수 없습니다.</p>
    <a href="{{ path('home') }}">홈으로 돌아가기</a>
  </div>
{% endblock %}

템플릿에서 사용 가능한 변수: status_code, status_text, exception(Throwable 객체).

개발 환경에서 미리보기

# config/routes/framework.yaml
when@dev:
  _errors:
    resource: '@FrameworkBundle/Resources/config/routing/errors.php'
    type: php
    prefix: /_error
$ # 브라우저에서 다음 URL 접근
$ # http://localhost:8000/_error/404
$ # http://localhost:8000/_error/500.json

운영 환경에서는 위 라우트가 자동 비활성화된다 (when@dev 가드).

6.7 Notifier — Email

Notifier 컴포넌트는 다양한 채널(이메일·SMS·Chat·Push)을 통합 인터페이스로 추상화한다. 트랜잭션 메일은 Mailer 컴포넌트로도 직접 발송 가능하다.

$ composer require symfony/mailer symfony/twig-pack

TemplatedEmail로 발송

use Symfony\Bridge\Twig\Mime\TemplatedEmail;
use Symfony\Component\Mailer\MailerInterface;
use Symfony\Component\Mime\Address;

final readonly class SendOrderConfirmation
{
    public function __construct(private MailerInterface $mailer) {}

    public function __invoke(Order $order): void
    {
        $email = (new TemplatedEmail())
            ->from(new Address('hello@shop.local', '심포니 쇼핑몰'))
            ->to($order->getCustomer()->getEmail())
            ->subject(sprintf('주문 #%d 접수', $order->getId()))
            ->htmlTemplate('email/order_confirmation.html.twig')
            ->textTemplate('email/order_confirmation.txt.twig')
            ->context(['order' => $order]);

        $this->mailer->send($email);
    }
}

환경별 트랜스포트

환경MAILER_DSN
개발smtp://mailer:1025 (Mailpit)
테스트null://null (실제 발송 차단)
SendGridsendgrid+api://KEY@default
Postmarkpostmark+api://KEY@default
AWS SESses+https://KEY:SECRET@default?region=ap-northeast-2

인앱 발송은 응답을 지연시킨다 (SMTP RTT 200~500ms). Messenger로 비동기 디스패치를 권장한다.

6.8 Notifier — Chat · SMS

Notifier는 “한 알림을 여러 채널로”가 핵심 가치다. 이메일 + Slack + SMS를 단일 디스패치로 발송한다.

$ composer require symfony/notifier \
    symfony/slack-notifier symfony/twilio-notifier
# .env
SLACK_DSN=slack://TOKEN@default?channel=alerts
TWILIO_DSN=twilio://SID:TOKEN@default?from=+1...

# config/packages/notifier.php
$notifier = $framework->notifier();
$notifier->chatterTransport('slack')->dsn('%env(SLACK_DSN)%');
$notifier->texterTransport('twilio')->dsn('%env(TWILIO_DSN)%');
$notifier->channelPolicy('urgent')
    ->channels(['sms', 'chat/slack', 'email']);
$notifier->channelPolicy('high')
    ->channels(['chat/slack', 'email']);

발송

use Symfony\Component\Notifier\Notification\Notification;
use Symfony\Component\Notifier\NotifierInterface;
use Symfony\Component\Notifier\Recipient\Recipient;

final class HighValueOrderNotice
{
    public function __construct(private NotifierInterface $notifier) {}

    public function __invoke(Order $order): void
    {
        $note = (new Notification('고액 주문 발생'))
            ->content(sprintf('주문 #%d, %s원',
                $order->getId(),
                number_format($order->getTotalKrw())))
            ->importance(Notification::IMPORTANCE_HIGH);

        $recipient = new Recipient(
            email: 'ops@shop.local',
            phone: '+821000000000',
        );

        $this->notifier->send($note, $recipient);
    }
}

importance가 channelPolicy의 키와 매칭되어 발송 채널이 결정된다. 라라벨의 Notification::via()와 같은 위상이지만 정책이 컴포넌트 설정으로 분리된다.

지원 트랜스포트(50개+): Slack, Discord, Teams, Telegram, Twilio, Vonage, Pushover, Firebase, OneSignal, Mattermost, Zulip 등.

6.9 Testing — Unit · Integration

심포니의 테스트는 PHPUnit 기반이며, 3 계층으로 구성한다.

  • Unit — 도메인·값 객체. 컨테이너·DB 미사용. TestCase 상속.
  • Integration — 컨테이너·DB 사용. KernelTestCase 상속.
  • Functional — HTTP 레벨. WebTestCase 상속.

Unit 테스트

// tests/Unit/Money/KrwTest.php
namespace App\Tests\Unit\Money;

use App\Money\Krw;
use PHPUnit\Framework\TestCase;

final class KrwTest extends TestCase
{
    public function test_addition_preserves_immutability(): void
    {
        $a = Krw::of(1000);
        $b = Krw::of(2500);
        $sum = $a->add($b);

        $this->assertSame(3500, $sum->amount);
        $this->assertSame(1000, $a->amount); // 원본 불변
    }

    public function test_negative_amount_throws(): void
    {
        $this->expectException(\InvalidArgumentException::class);
        Krw::of(-1);
    }
}

Integration 테스트

// tests/Integration/Repository/ProductRepositoryTest.php
final class ProductRepositoryTest extends KernelTestCase
{
    public function test_search_filters_zero_stock(): void
    {
        $em = self::getContainer()->get(EntityManagerInterface::class);
        $repo = self::getContainer()->get(ProductRepository::class);

        $em->persist((new Product())->setName('A')->setStock(0));
        $em->persist((new Product())->setName('B')->setStock(5));
        $em->flush();

        $hits = $repo->searchByKeyword('');
        $this->assertCount(1, $hits);
    }
}

실행: php bin/phpunit --testsuite Unit.

6.10 Testing — Functional

WebTestCase는 실제 HTTP 라이프사이클을 시뮬레이션하는 클라이언트를 제공한다. 컨트롤러·라우트·Twig·Security를 포함한 전 흐름을 테스트한다.

// tests/Functional/Controller/CatalogTest.php
namespace App\Tests\Functional\Controller;

use Symfony\Bundle\FrameworkBundle\Test\WebTestCase;

final class CatalogTest extends WebTestCase
{
    public function test_index_lists_products(): void
    {
        $client = static::createClient();
        $client->request('GET', '/products');

        $this->assertResponseIsSuccessful();
        $this->assertSelectorTextContains('h1', '상품 목록');
        $this->assertSelectorCount(12, '.product-card');
    }

    public function test_show_returns_404_when_missing(): void
    {
        $client = static::createClient();
        $client->request('GET', '/products/nonexistent');
        $this->assertResponseStatusCodeSame(404);
    }

    public function test_admin_create_requires_login(): void
    {
        $client = static::createClient();
        $client->request('GET', '/admin/products/new');
        $this->assertResponseRedirects('/login');
    }

    public function test_logged_in_admin_can_create(): void
    {
        $client = static::createClient();
        $admin = static::getContainer()->get(UserRepository::class)
            ->findOneBy(['email' => 'admin@shop.local']);
        $client->loginUser($admin);

        $crawler = $client->request('GET', '/admin/products/new');
        $form = $crawler->selectButton('저장')->form([
            'product[name]' => '테스트 상품',
            'product[priceKrw]' => '15000',
        ]);
        $client->submit($form);
        $this->assertResponseRedirects();
    }
}

주요 어서션: assertResponseIsSuccessful, assertResponseRedirects, assertSelectorTextContains, assertSelectorExists.
