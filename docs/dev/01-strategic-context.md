# 01. 전략적 맥락 — 왜 이 시스템이 존재하는가

## 1. 풀려는 문제

이 코드베이스는 **다(多)테마 × 지역 키워드의 12개월 SEO 권위 구축** 문제를 푸는 도구입니다.

구체적으로:
- 사용자는 *여러 테마*(예: 과외, 학원, 학습 콘텐츠)를 운영한다
- 각 테마는 *지역별*로 검색 의도가 갈린다 (예: "강남 과외", "강남 학원")
- 즉 키워드 공간은 **테마 × 지역의 매트릭스**다
- 매트릭스에는 수천 개의 칸이 있고, 각 칸이 잠재적 페이지다
- 12개월 안에 Google에서 *지속 가능한 권위*를 구축해야 한다

문제의 본질:
- 매트릭스 안 *모든 칸*에 페이지를 만들면 사이트가 무너진다 (2026년 3월 Google 업데이트로 60~90% 트래픽 감소를 겪은 사이트들의 공통 행동)
- *너무 적게* 만들면 권위가 안 쌓인다
- **"어디에 페이지를 만들지"가 가장 중요한 결정**이고, 이 결정을 *시스템이 강제로 도와줘야* 한다

## 2. 왜 단순한 CMS로는 부족한가

기존 CMS(Wordpress, Strapi, Sanity 등)의 가정:
- *페이지는 운영자가 만들고 싶을 때 만든다*
- *페이지의 발행 여부는 운영자가 판단한다*
- *URL은 운영자가 정하거나 슬러그를 입력한다*

이 가정들은 **개수가 작은 사이트**(블로그, 회사 소개, 제품 카탈로그)에서는 합리적입니다. 하지만 *수천 개 잠재 페이지가 있는 매트릭스 사이트*에서는 모두 잘못된 가정입니다:

| CMS 가정 | 매트릭스 사이트의 현실 |
|---|---|
| 운영자가 페이지 만들 시점 결정 | 데이터가 충분한 칸은 *자동으로 후보*가 되어야 함 |
| 운영자가 발행 여부 판단 | 발행 게이트가 *주관적이면 무너짐* — 객관 규칙 필요 |
| 운영자가 URL 정함 | URL은 *(theme, region) 좌표의 함수*여야 — 손으로 만들면 카니발리제이션 |
| 페이지 = 콘텐츠의 단위 | 페이지 = *데이터가 채워진 좌표* (콘텐츠는 데이터에서 합성) |

이 가정 차이가 *시스템 설계의 거의 모든 결정*을 좌우합니다.

## 3. 핵심 통찰 — "단 하나의 결정 변수"

전략 문서가 강조하는 가장 중요한 한 문장:

> **"테마 × 지역" 매트릭스에서, 실제로 우리가 *고유 데이터를 채울 수 있는 칸*이 몇 개인가?**

이 숫자가 *최종 도달 가능한 페이지 수의 상한*입니다.

- 100개 칸을 채울 데이터가 있다면 → 100페이지
- 7,500개 칸을 만들지만 데이터로 채울 수 있는 게 200개라면 → *7,300개는 약한 페이지가 되어 사이트 전체*를 무너뜨린다

**채울 수 있는 칸의 정의** (3가지를 모두 만족):
1. 그 칸에 *최소 5개의 고유 데이터*를 채울 수 있는가
2. 그 데이터가 *템플릿 변수 치환이 아닌 진짜 다른 값*인가
3. 사용자가 도착했을 때 *이전 페이지에 없는 정보*를 얻는가

세 질문에 모두 *예*인 칸만 페이지가 됩니다. 이 정의는 코드베이스의 **publish gate** (`fn_publish_gate` 트리거)에 그대로 인코딩되어 있습니다.

## 4. 왜 12개월인가

12개월이라는 기간은 임의가 아닙니다. 다음 4가지 단계가 *순서대로* 진행되어야 합니다:

| 단계 | 기간 | 이유 |
|---|---|---|
| **권위 시드** | 1~3개월 | 허브 페이지 25~35개로 토픽 권위의 *씨앗*을 심음. Search Console에 첫 노출(impression) 등장. |
| **광역 확장** | 4~6개월 | 시도(17개) 단위로 첫 매트릭스 row 채움. Google이 *어떤 키워드가 통하는지* 신호를 보냄. |
| **신호 기반 좁힘** | 7~9개월 | Search Console 신호 받은 시군구만 발행. 무차별 확장 X. |
| **세부 정착** | 10~12개월 | 인덱스된 시군구의 동 단위로만 확장. 약한 페이지 정리 강화. |

**왜 이 순서를 못 줄이나:**
- Google이 신규 페이지를 인덱스하고 신호를 평가하는 데 *최소 2~3개월*이 걸림
- 단계를 건너뛰고 바로 동 단위로 가면 *어떤 동이 통할지 신호 없이* 추측해야 함 → 약한 페이지 양산
- 신호 없이 만든 페이지는 *권위를 깎아먹음* (전체 도메인 평가 하락)

12개월 = *Google의 평가 사이클을 4번 겪고, 매번 신호를 보고 다음 행동을 결정할 수 있는 최소 시간*.

## 6. 무엇을 풀지 *않는가*

명시적으로 이 시스템이 다루지 않는 것:

| 영역 | 왜 안 다루는가 |
|---|---|
| 백링크 빌딩 | *외부* 사이트의 행동 — 별도 영업 활동 |
| 콘텐츠 라이팅 자체 | LLM 보조는 가능하나 *최종 작성은 운영자* |
| 광고/유료 트래픽 | SEO는 *유기적* 트래픽만 다룸 |
| 다국어 | 단일 언어 가정. i18n 추가는 별도 |
| Year 2 이후 | 12개월 도달 후 운영 모드는 별도 설계 |

이 경계를 명확히 하는 이유: *이 시스템이 풀어줄 거라고 잘못 기대하는 것*을 막기 위함입니다.
