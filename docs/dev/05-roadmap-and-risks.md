# 05. 12개월 로드맵과 위험 — 왜 이 순서인가

## 1. 페이즈 구조의 본질

12개월 SEO 로드맵은 *임의의 일정*이 아닙니다. 다음 두 *외부 제약*이 페이즈 순서를 강제합니다:

1. **Google의 평가 사이클**: 새 페이지 인덱스 + 신호 평가에 *최소 2~3개월* 필요
2. **신호 기반 의사결정 원칙**: 다음 발행은 *이전 페이즈 신호*를 보고 결정해야 약한 페이지 양산을 막을 수 있음

이 두 제약이 **Phase 0 → 1 → 2 → 3 → 4의 강제 순서**를 만듭니다.

## 2. 왜 12개월인가

### 2.1 더 짧으면 안 되는 이유

| 제안 | 왜 안 되는가 |
|---|---|
| 6개월 | 첫 신호(Phase 1 노출)가 Month 3에 시작 → 신호 기반 결정을 위한 시간 절반 |
| 3개월 | Google 인덱스 사이클 1번도 못 채움 → 권위 시드 안 됨 |
| 1개월 | 페이지 수만 늘어남 → 약한 페이지 양산 → 사이트 사망 |

### 2.2 더 길어도 되는가

| 제안 | 평가 |
|---|---|
| 18~24개월 | OK, 더 안전. 권장 시작점이 12개월. |
| Year 2+ | 다른 동학(외부 백링크, AI 검색 변화) → 별도 설계 필요 |

12개월은 *최소 합리적 기간*. 짧으면 위험, 길면 더 안전.

## 3. Phase 0 — 인프라 (Week 1~2)

### 3.1 산출물

이 페이즈에서 페이지는 **0개** 발행. 다음 인프라만:

- 5개 엔티티 DB 스키마
- 6개 트리거 (publish gate 등)
- DataPoint 입력 UI
- URL 라우터 + 자동 sitemap.xml
- Theme 3~5개, Region 트리 시드 (한국 행정구역 ~3,750개)

### 3.2 왜 페이지 0개인가

페이지 발행을 *빨리 시작하고 싶은 충동*을 막기 위함.

데이터 게이트 + 입력 시스템 없이 시작하면:
- 게이트 만들기 전에 약한 페이지 발행됨
- 나중에 게이트 추가 시 *이전 페이지를 강등*해야 → 운영 혼란

게이트가 *처음부터* 켜져 있어야 모든 페이지가 같은 기준 통과.

### 3.3 가장 흔한 실수

> "Region 시드 없이 시작하자, 나중에 추가하면 되니까"

이러면 첫 ContentNode 만들 때 region을 직접 입력하다가 실수. 일관성 깨짐. **Region 트리는 시작 시점에 *완전히* 시드해야** 합니다.

## 4. Phase 1 — 깊은 허브 (Month 1~3)

### 4.1 산출물 25~35개

| 종류 | 개수 | 분량 |
|---|---|---|
| 사이트 루트 허브 | 1 | 5,000자+ |
| 테마 허브 | 3~5 | 3,000자+ |
| 정보형 가이드 | 15~25 | 1,500자+ |
| 작성자/회사 신뢰 | 3~5 | 중간 |

**모두 region=NULL** 노드. 지역 페이지는 *발행 안 함*.

### 4.2 왜 지역 페이지를 안 만드는가

Phase 1의 목적은 *토픽 권위 시드*:
- 허브 페이지가 깊으면 → Google이 *이 사이트는 X 토픽에 권위*라고 인식
- 지역 페이지를 미리 만들면 → 권위 안 잡힌 상태에서 노출 0
- 토픽 권위가 잡히면 → Phase 2의 지역 페이지가 *동시에 인덱스됨*

### 4.3 가장 큰 위험 — Month 2~3 충돌

Phase 1의 가장 위험한 시점:

> 발행 후 2~3개월. 노출은 약간 있지만 클릭은 0에 가깝다. *기다림이 한계에 다다른다.*

이 시점에 다음 충동이 *반드시* 옵니다:

1. "AI로 동 페이지 3,500개 한 번에 만들면?"
2. "발행 게이트를 끄고 100개라도 빨리 발행?"
3. "다른 SEO 컨설턴트 의견 들어봐?"

**대응**:
- DB 트리거가 1, 2번을 코드 레벨에서 차단 ([03. publish-gate-design](03-publish-gate-design.md))
- 3번에 대한 답: *모든 컨설턴트가 같은 답을 합니다 — 기다리세요*. 다른 답을 하는 컨설턴트는 위험.

이 시기를 견디는 게 *12개월 계획의 가장 큰 시험*.

## 5. Phase 2 — 시도 광역 (Month 4~6)

### 5.1 산출물 50~60개

- 테마 × 시도 페이지 (3 × 17 = 51)
- 신규 정보형 글 10~15

### 5.2 왜 시군구가 아닌 시도부터인가

권위는 *위에서 아래로* 흐릅니다:
- 테마 허브 → 시도 → 시군구 → 동
- 시도가 인덱스 안 된 상태에서 시군구 만들면 → 시군구도 인덱스 안 됨

시도 17개를 먼저 채우면 *Google이 어떤 키워드 조합이 통하는지* 신호를 줍니다. 이 신호가 Phase 3 결정의 입력.

### 5.3 일부 시도가 noindex되는 것은 정상

데이터가 부족한 시도(예: 인구 적은 시)는 자동으로 `noindex`. 이게 정상입니다 — 약한 시도 페이지를 발행하면 *전체 사이트의 평균*을 낮춤.

## 6. Phase 3 — 신호 기반 시군구 (Month 7~9)

### 6.1 산출물 110~210개

- 시군구 페이지 (228개 중 신호 받은 것만)
- Search Console 데이터로 학년/과목 조합 발견

### 6.2 결정 규칙

Phase 3의 *발행 결정*은 다음 두 조건 중 **하나라도 만족**해야:

1. Search Console에서 *그 시군구 키워드로 검색 발생*
2. *데이터(매칭/리뷰/콘텐츠) 5개 이상* 모을 수 있음

**둘 다 만족 못하면**: 그 시군구는 *상위 시도 페이지의 섹션*으로만 처리. 자체 페이지 안 만듦.

### 6.3 왜 무차별 확장 안 하나

228개 시군구 모두 발행하면:
- 80%는 트래픽 0
- 약한 페이지가 도메인 평균을 끌어내림
- 강한 페이지의 권위까지 깎임

신호 없는 곳은 *영원히 안 만들어도 됨*. 12개월 후 사이트가 강해지면 *그 시점에* 추가 검토.

## 7. Phase 4 — 동 단위 + 정리 (Month 10~12)

### 7.1 산출물 150~400개

- 인덱스된 시군구의 동 페이지
- 학년/과목 깊은 조합
- **약한 페이지 10~20% 정리**

### 7.2 왜 정리가 발행만큼 중요한가

12개월 차에 약한 페이지가 누적되어 *도메인 권위를 깎고 있음*. Phase 4의 절반은 *발행이 아닌 정리*:

- 통합: 약한 페이지 데이터를 강한 페이지로 머지
- 폐기: status=dead → 자동 301
- 보강: 데이터 추가해서 강한 페이지로 승격

정리 안 하면 Year 2 시작 시점에 *부채를 떠안고 출발*. 권위가 안 늘어남.

## 8. 12개월 후 도달 가능 페이지 수

전략 문서가 제시한 현실적 범위:

```
Phase 1 (허브 + 정보형)     = 25 ~  35개
Phase 2 (시도)              = 50 ~  60개
Phase 3 (시군구)            = 110 ~ 210개
Phase 4 (동 + 조합)         = 150 ~ 400개
─────────────────────────────────────────
합계                         = 335 ~ 705개
```

이 숫자가 *왜 정확히 이 범위인가*:

- **하한 (335개)**: 운영자 1명, 외부 데이터 자동화 없음, 수동으로만 입력. 이래도 12개월 의미 있는 권위 가능.
- **상한 (705개)**: 외부 데이터 파이프라인 작동, 운영자 2명, 자동 추출 활용. 이 이상은 약한 페이지 위험.

**100개 미만이면**: 매트릭스 사이트로의 임계 미달. 일반 블로그가 더 효율적.
**700개 이상이면**: 약한 페이지 위험. 12개월에 도달하기 어렵고 도달해도 정리 부채 큼.

이 범위가 *시스템 설계의 모든 용량 결정*의 근거입니다 (DB 스키마, 캐시 전략, 매트릭스 화면 UX 등).

## 9. 4가지 위험과 완화

### 9.1 위험 1 — Month 2~3 트래픽 0의 유혹

**증상**: Phase 1 발행 후 두 달 째 클릭 0.

**자연스러운 충동**: AI로 페이지 양산.

**완화**:
- DB 트리거가 양산 자체를 차단 (publish gate)
- 운영자에게 *이 시기는 정상*이라고 사전 교육
- KPI 지표가 노출(impression)이지 클릭이 아님을 명시

### 9.2 위험 2 — 카니발리제이션

**증상**: 같은 키워드 두 페이지가 노립. 둘 다 인덱스되지만 어느 쪽도 1페이지 못 감.

**자연 발생 시나리오**:
- 시도 페이지와 시군구 페이지가 같은 머리어 ("서울 과외" vs "강남 과외")
- 학년 페이지와 학년+과목 페이지 충돌
- 새 정보형 글이 기존 가이드와 중복

**완화**:
- `(theme_id, region_id)` UNIQUE 제약이 *직접적 카니발리제이션* 차단
- 분기마다 [/admin/search](http://localhost:8000/admin/search)로 카니발 의심 페어 점검
- 의심 페어 발견 시 *통합* (강한 쪽에 데이터 머지)

### 9.3 위험 3 — 약한 페이지 누적

**증상**: 트래픽 0 페이지가 30%를 넘음. 도메인 평균 순위 하락.

**왜 발생**:
- 발행 시점에 강했으나 시간 지나며 약해짐 (정보 진부화)
- 데이터 부족인데 발행 게이트 우회 (Phase 0 미완료 시)
- 분기 정리를 안 함

**완화**:
- 분기 정리가 *체계적 루틴*이어야 함 ([OPERATIONS.md §3](../../OPERATIONS.md))
- *방치는 선택지가 아니다*: 살리거나, 통합하거나, 삭제
- 30% 임계 넘으면 발행 동결 + 정리만

### 9.4 위험 4 — 테마 분산

**증상**: 테마 5개 이상으로 늘어남. 어느 테마에서도 권위가 안 잡힘.

**왜 발생**:
- "이 도메인 비어 있으니 우리도 다루자" 충동
- 운영자 전문성보다 *시장 기회* 우선시

**완화**:
- Phase 0에서 테마 *3~5개로 제한*
- 새 테마 추가는 *기존 테마 중 가장 깊은 것이 충분히 권위 있을 때*만
- Theme.depth ≤ 2 제약이 *간접적으로* 분산을 제한

## 10. 페이즈 진행의 KPI 게이트

각 페이즈를 다음 페이즈로 넘기 전 확인할 *최소 신호*:

| 페이즈 종료 | 최소 신호 | 미달 시 |
|---|---|---|
| Phase 1 → 2 | Search Console 일 노출 100+ | Phase 1을 1개월 더 (보강) |
| Phase 2 → 3 | 시도 페이지 일부가 50위 이내 | Phase 2 시도들 데이터 보강 |
| Phase 3 → 4 | 시군구 일부가 10위 이내 | Phase 3 신호 받은 시군구만 동 단위 확장 |
| Phase 4 종료 | 자연 검색 일 방문자 800+ | Year 2 동안 정리 + 권위 콘텐츠 (리포트) 강화 |

이 게이트들이 *맹목적 페이즈 진행*을 막습니다. 신호가 없으면 다음 페이즈로 안 넘어갑니다 — 이게 12개월 동안 *복구 불가능한 실수를 안 만드는* 단일 규칙입니다.

## 11. 시스템이 페이즈 진행을 *돕는* 방법

이 코드베이스가 페이즈 진행을 어떻게 돕는지:

| 페이즈 | 시스템 지원 |
|---|---|
| Phase 0 | 시드 명령어 (`app:seed:demo`), 마이그레이션, fixtures |
| Phase 1 | 가이드/허브 발행 게이트 (별도 룰), prose 템플릿 변종 |
| Phase 2 | 매트릭스 시드, 시도 단위 데이터 입력 UI |
| Phase 3 | KPI 히트맵, 카니발 검출, 신호 기반 발행 후보 추천 |
| Phase 4 | 자동 리다이렉트, 약한 페이지 큐, 분기 정리 도구 |

코드베이스의 모든 기능이 *어느 페이즈에서 어떻게 쓰이는지* 명확합니다. 기능이 *언제 쓰일지 모르고 만든 게 없습니다*.

## 12. Year 2 이후 — 이 시스템이 다루지 않는 영역

12개월 도달 후 운영 모드는 *별도 설계*가 필요합니다. 이 시스템이 다루지 않는 것:

- 외부 백링크 자동 모니터링
- 경쟁사 분석
- 다국어 (i18n)
- AI 검색(Perplexity, ChatGPT) 인용 추적의 자동화
- A/B 테스트 인프라

Year 2 시작 시점에 *이 영역들이 필요한지* 평가하고, 필요하면 별도 모듈로 추가합니다.

## 13. 마무리 — 이 시스템의 약속

이 시스템이 약속하는 것:

> *데이터만 잘 만지면 12개월 동안 사이트가 무너지지 않는다.*

약속하지 않는 것:

> *12개월 후 반드시 성공*. (시장 상황, 콘텐츠 품질, 외부 변수에 따라 결과 변동)

시스템이 *최선의 환경*을 만들어주지만, *콘텐츠의 본질적 가치*는 운영자가 만듭니다. 시스템 = 안전망, 운영자 = 가치 창출.
